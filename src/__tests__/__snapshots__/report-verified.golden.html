Before you share this

This report was made on one machine from transcripts already on its disk, and the scan sent nothing anywhere.

Every command in this report has been through a secret scrubber, a path redactor, a pass for secret-named values and long random-looking strings, and an identifier redactor, and every MCP tool call has had its payload values structurally redacted. Redaction runs before anything is written, so this file has never held the original text.

stands for a redacted MCP payload value

Redaction is thorough but not a guarantee. Read the findings before posting this anywhere public, and run agenttrail-guard scan --agent claude --review to see every line before the file is written.

How redaction works and where it can miss

Working directories and file paths appear nowhere in this file, and the projects these sessions came from are carried as a count and never as names.

Identifying names are a weaker claim than paths, and the difference is worth knowing. Shell commands go through an identifier redactor keyed to a fixed list of tools — container runtimes, kubectl (including resource names), the database clients (host, database, and the SQL handed to -c / -e), ssh, git commit messages and identity settings, 1Password's op (item and vault names), and gh titles and bodies — plus, in any command, a secret passed as a flag value (--token, --password, --key), a UUID, the body of a heredoc, and the text of a # comment. That list is a deny-list and will miss the tool nobody thought of, so a bare operand naming a resource for a tool not on it can survive.

Cloud account identifiers are redacted where a name or flag gives them away: CLOUDFLARE_ACCOUNT_ID and --account-id, wrangler commands, AWS account numbers after --account or inside an ARN, and --project for gcloud, gsutil, bq and firebase.

Secrets without a known format are caught by name and by shape, and both are guesses. A value after a name ending in _KEY or -key, an Authorization header, and any long random-looking string of 32 or more characters is masked. A secret that is shorter, that is only hexadecimal and has no revealing name, that is split by punctuation, or that has no name and is followed by a ., ends in = or is written as short dashed groups can survive. Branch names, folder names and git branch operands are kept readable and are not redacted.

MCP tool calls are handled the other way round: a call to an MCP server arrives as a structured payload, and rather than deny-listing known-sensitive fields, every value in it is redacted to <value> by default and only the field names and the shape are kept.

Guardrail ids and titles are shown as their author wrote them — which for any guardrail you added yourself means your own words, unredacted. Redaction is thorough but not a guarantee. Read the commands and guardrail names above before posting this anywhere public.
